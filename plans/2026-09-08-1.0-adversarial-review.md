## Actionable findings (2+ confirmations)

### Critical (7)

- **`SwiftUI/EdgeStudio/Data/MCPServer/MCPHTTPParser.swift:113`** — crash — _adjudicated_  
  A negative hex chunk-size in a `Transfer-Encoding: chunked` request makes `decodeChunkedBody` construct a reversed Range, trapping and killing the whole Edge Studio process before the request ever reaches the JSON-RPC layer.
- **`SwiftUI/EdgeStudio/Views/StudioView/Details/TransportConfigView.swift:355`** — state-desync — _pair (cross-area)_  
  Applying transport settings calls SystemRepository.stopObserver(), which nils the sync-status and connections callbacks, but only the SDK observers are re-registered afterwards — the callbacks are never reinstalled, so the Peers List and connection status bar go permanently dead until the database is reopened.
- **`android/app/src/main/java/com/costoda/dittoedgestudio/data/repository/DatabaseRepositoryImpl.kt:40`** — data-loss — _pair_  
  Saving a database config whose `databaseId` already exists silently REPLACEs the existing row and, because foreign keys are ON, cascade-deletes every subscription, observer, favorite and history row belonging to that database — with no warning and no undo.
- **`android/app/src/main/java/com/costoda/dittoedgestudio/ui/database/DatabaseListScreen.kt:87`** — data-corruption — _pair_  
  On tablet/expanded widths the database editor's ViewModel key is derived from a plain `remember` counter that resets whenever DatabaseListScreen leaves the composition, while the NavEntry ViewModelStore survives — so a later edit re-uses a retained ViewModel constructed for a DIFFERENT database row. The editor displays and then overwrites the wrong database.
- **`android/app/src/main/java/com/costoda/dittoedgestudio/ui/qrcode/QrDisplayDialog.kt:36`** — credential-exposure — _adjudicated_  
  The QR-share dialog resolves its ViewModel under the class-default ViewModel key, so after the first use it always re-serves the FIRST database's credentials — every later database shows the wrong config (including the wrong auth token and secret key) under the right database's name.
- **`android/app/src/main/java/com/costoda/dittoedgestudio/ui/qrcode/QrScannerViewModel.kt:60`** — data-loss — _adjudicated_  
  Importing a QR config for a database that is already registered silently cascade-deletes that database's subscriptions, observers, favorites and query history, and reports success.
- **`android/app/src/main/java/com/costoda/dittoedgestudio/util/QrCodeEncoder.kt:23`** — cross-platform-contract-break — _pair_  
  Android's database-config QR encoder uses kotlinx.serialization's default `encodeDefaults = false`, so it omits `_id` from every EDS2 payload (and `favorites` when the sender has none), while the SwiftUI decoder requires both keys unconditionally — every database QR code produced by the Android app is undecodable on macOS/iPadOS.

# Android red build — resolved (2026-09-08)

`SystemRepositoryTest > mesh aggregation includes edges only the local peer advertises`
(`expected:<local> but was:<>`).

**Fixed on the user's explicit instruction.** It was a single-source finding (mine), which the
two-reviewer rule would otherwise hold at "recorded, not fixed"; the user directed the fix.

## It was a test-harness race, and that is now proven, not asserted

`SystemRepositoryImpl` hardcoded `metricsScope = CoroutineScope(SupervisorJob() + Dispatchers.IO)`.
`updatePresence` awaits `fetchSyncMetricsBestEffort` — which hops to that scope under a
`withTimeoutOrNull` — *before* assigning `_meshTopology`. The test drives collection on
`Dispatchers.Unconfined` and reads `meshTopology.value` synchronously after `startObserving`,
so the read raced an assignment that had not happened yet.

**The fix changes no production logic.** `metricsDispatcher` is now a constructor parameter
defaulting to `Dispatchers.IO`, exactly as `StudioSession` already does for `ioDispatcher` /
`teardownDispatcher`. The test passes `Dispatchers.Unconfined`. The test then passes — with the
production code path byte-for-byte unchanged — which is the evidence that the product was never
broken.
